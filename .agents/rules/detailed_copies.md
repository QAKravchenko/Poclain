# Правило ведения файлов с подробными подсказками (Detailed Copies)

## 1. Чистота основных рабочих файлов
- В папках `tests/` и `pages/` (в подпапках `prod/`, `pre-prod/`, `practice/`) основные файлы (`*.spec.ts`, `*.ts`) должны содержать чистый, лаконичный код без избыточных построчных комментариев-подсказок.

## 2. Создание подробных копий (detailed)
- Для каждого файла из папки `tests/<env>/` создавать копию в папке `tests/<env>/detailed/` с именем `<имя_файла>.detailed.spec.ts`.
- Для каждого файла из папки `pages/<env>/` создавать копию в папке `pages/<env>/detailed/` с именем `<имя_файла>.detailed.ts`.
- В detailed-копиях каждая строка кода снабжается подробными подсказками и объяснениями на русском языке (что делает импорт, локатор, метод, assertion, переданные параметры).

## 3. Конфигурация запуска
- Все папки `detailed/` исключены из стандартного прогона тестов (`testIgnore: ['**/detailed/**']` в `playwright.config.ts`), чтобы избежать дублирования тестов в отчетах. При необходимости любой detailed-тест можно запустить напрямую по пути к файлу.

## 4. Язык подсказок и комментариев
- Все подсказки, комментарии, JSDoc-описания и пояснения во ВСЕХ файлах проекта (включая подробные копии `detailed`, файлы конфигурации `playwright.config.ts`, `config/environment.ts`, переменные `.env`, тесты и тестовые данные) должны быть строго на русском языке.

## 5. Ограничения проекта Poclain
- Не создавать и не восстанавливать файлы `articles.spec.ts`, `ArticlesPage.ts` и связанные с ними данные (они относятся к другому проекту QA Dojo).
